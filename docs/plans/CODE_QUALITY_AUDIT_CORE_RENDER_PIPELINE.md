## 1. 结论与使用方法

当前管线有两项应优先修复的正确性问题：**无有效层的效果栈矩形会回流基础绘制路径；文字依赖环会让渲染无法结束。** 此外，Logo 入参回写、匹配上下文不一致，以及矩形和几何逻辑重复，增加了维护成本。

先修复可独立验证的问题，再收敛结构。不要把修复与大规模拆分混成一个改动，也不要把所有建议都当作“输出像素不变”的重构。

交接给执行智能体时：

1. 先读 §2 的行为边界，按 §7 选择任务包。
2. 通过 Q 编号查 §3–§6 的证据、动作与验收要求。Q1–Q15 沿用原编号，便于对照历史讨论。
3. 先留存修改前证据，再实施；使用 §8 的验收矩阵区分“预期修复差异”和“必须保持一致”的行为。
4. 涉及尚未确定的行为策略时，先完成兼容调查；无法确定则提出具体问题，只暂停依赖该决定的部分，继续其他已明确的任务。

本文审计存量结构，未对比引入问题的历史 diff，因此不将这些问题称为“新增回归”。文件接近 1000 行是维护信号，不能单独作为 P0 或发行阻断依据。代码质量改进应减少重复决策和隐式状态，而不只是把代码搬到更多文件。

## 2. 实施前必须保持的行为边界

以下边界已由源码、样式指南或复核确认，执行时直接保留：

| 边界 | 要求 |
|---|---|
| 图层顺序 | legacy 矩形在原图下方；效果栈在原图上方、装饰器之前；文字、Logo 的既有顺序保持不变 |
| 效果栈分流 | 显式存在 `fill`，或开启 stroke/gaussian_blur，决定效果栈身份；身份与是否有有效层分开 |
| 矩形 padding | 矩形不受安全区夹持，这是设计要求；文字树延迟到整树定位后再夹持 |
| 数值单位 | padding 的数值按参照边比例；margin 的整数是像素、浮点数是比例 |
| Logo 三态 | 当前 `None` 为自动、`""` 为禁用、非空文件名为固定选择；不得用 `or None` 合并前两种状态 |
| 高斯短路 | 背景不可见时可以跳过卷积，但后续仍需要尺寸正确的承载画布 |
| 模糊取样 | 效果栈按既有冻结原图缓存取样；保留照片内/跨界分类、裁切、圆角和单次组蒙版语义 |
| 合成精度 | 等价重构保持逐矩形顺序及中间量化；不能用“视觉差不多”替代逐像素验收 |
| 运行环境 | 遵循 AGENTS.md；PowerShell 先激活 venv，新增资源路径走 app_paths，生产改动留在 dev |

下面几项尚不能直接统一。默认先保留当前行为，调查结论写入对应任务的实施记录；只有确实需要改变且依据不足时才询问用户：

| 待定事项 | 可以先做 | 改变行为前需要补齐 |
|---|---|---|
| Q6 原始品牌与映射后品牌 | 记录两种输入及匹配结果，明确最终背景来源 | 全量映射表比对；选择统一品牌来源并列出匹配差异 |
| Q8 非法颜色如何处理 | 抽取共同解析步骤，保持调用方现有失败策略 | 明确哪些输入抛错、回退或跳过，记录行为变化 |
| Q11 是否取消后缀匹配 | 统一查找函数，保留精确优先和现有遍历顺序 | 核对内置/可获得的用户样式引用；无法排除依赖时保留兼容行为 |
| Q12 超大盒优先贴哪边 | 复用普通盒与相对定位末尾的相同公式 | 明确普通盒、组合盒、整树放不下时的共同策略 |
| Q14-11 是否删除定位键过滤 | 保留现有过滤 | 若改变边界，同步修订矩形设计文档第 11 条 |

## 3. 优先修复的正确性与契约问题

### Q3：效果栈身份与有效绘制层混在一起

**证据。** `renderer.py:_rect_is_effect_stack`（151–169）按配置决定身份；`_analyze_rectangles`（583–585）丢弃无有效层的矩形；`render_frame`（810）却仅用保留下来的 spec 生成 `stack_names`。被丢弃的效果栈矩形因此没有进入排除名单，随后被 `_draw_rectangles` 当作 legacy 绘制。

**已实测的最终成品错误。** 使用 100×100 蓝色照片、底部扩展 50px、宽 50 高 20 的红色矩形，位置为 `bottom-center + top-center`，显式 `fill.enabled=false` 且其余层关闭。最终边框点 `(50,110)` 是红色；按配置应为白色背景。若同一矩形完全在不透明照片内部，错误绘制会被照片盖住，因此不能只采样中间背景图来判断成品影响。

**执行动作。** 先做最小修复：legacy 排除名单按“是否属于效果栈”生成，不依赖分析结果是否保留 spec。矩形属于效果栈但三层无效时，保持不绘制；完全在画布外时同样不能回流。之后再由 Q1/Q2 的统一计划接替这套分流，避免长期重复分类。

**验收。** 完整 `render_frame` 验证边框、照片内和跨界情形；三层关闭、逐层非法降级、透明填充、无效尺寸和完全在画布外均覆盖。上述红色边框点修复后应为白色；正常 legacy 与有效效果栈保持原像素。尺寸小于 1px 的情况单列验证，不凭比例为正就认为有有效面积。

### Q14-12：依赖环可使文字渲染无法结束

**证据。** `text_renderer.py:378–387` 的 `while walk` 向上找根，没有 visited 集合；`_resolve_element_order`（197–199）把拓扑排序未处理节点直接补回；`style_manager.py:_validate_positioning`（404–426）只校验节点字段，未拒绝环。`LayoutEngine._shift_dependents` 与 `_collect_tree_members` 也无环保护。

**已实测。** 有实际文本的 `a.relative_to=b, b.relative_to=a` 通过样式校验；真实渲染中 walk 持续 `a,b,a,b…`。复核用 tracing 在第 12 次进入循环时主动中止，没有让进程持续挂死。

**执行动作。** 在配置边界校验依赖图并拒绝环，错误中给出节点链；运行时向上遍历和递归也应有明确的有界防御，覆盖绕过 StyleManager 直接调用渲染器的路径。不能靠静默忽略节点、返回部分结果或只增加递归深度掩盖问题。共享依赖分析时保持当前三类文字来源的合并规则。

**验收。** 覆盖自环、双节点环、较长环、正常多级链、没有实际文本的环，以及缺失目标。环应受控报错且不挂死；缺失目标按现有规则处理，合法链的顺序、坐标与像素不变。不要用无超时保护的 GUI 操作复现挂死。

### Q5：自动 Logo 匹配回写调用方 options

**证据。** `renderer.py:910–917` 将自动结果写入 `options.logo_filename`。复用同一 options 渲染 Canon、Nikon 时，复核只观察到一次自动匹配。当前主要调用方每次新建或逐帧重设字段，所以这证明接口复用风险，不证明所有正常批次都已出错。

**执行动作。** 使用局部有效 Logo 文件名，整帧不回写 options。保留自动、禁用、固定文件三态。此项可独立完成，不依赖 Q6 的模式模型重构。

**边界。** `batch_processor.py:225–227` 的注释防止将空串禁用转换为 None 自动，**停止回写后仍然有用，必须保留**。只有三态边界真正被替换后，才同步更新该注释。

**验收。** 相同 options 连续渲染不同品牌和不同有效背景，每帧自动重选；调用前后 options 字段不变。禁用时不自动匹配，固定文件不被重选。正常单帧输出不变。

### Q6：Logo 决策重复，且匹配上下文不一致

**证据。** 当前 renderer、批处理、PySide GUI 和封存的 legacy GUI 都有自动匹配决策。它们不只是重复调用，输入语义也不同：

| 路径 | 品牌来源 | 背景来源 |
|---|---|---|
| `batch_processor.py:205–213` | 原始 EXIF Make，经 strip/lower | 用户选择的 `bg_fill_type` |
| `gui_pyside/pages/image_processing_page.py:1393–1396` | 同上 | 用户选择的 `bg_key` |
| `renderer.py:909–917` | RenderContext 的显示品牌，可能经过设备映射 | 样式覆盖之后的 `effective_bg_type` |

用户选择白背景、样式覆盖为黑背景时，上游可能先固定普通 Logo；renderer 收到非空文件名便不会按最终背景改选白色 Logo。复核以受控选择器验证该决策链，并用真实 `LogoSelector.auto_match_logo` 确认两种明暗会选不同变体；尚未做真实 GUI 全链验证。

**执行动作。**

1. 区分用户固定选择和上游自动预选结果，使自动模式能够在最终背景确定后统一匹配。
2. 比对原始/映射后品牌的匹配结果，明确统一品牌来源；不要静默切换来源。
3. 将自动/禁用/固定模式在边界处规范化。可以采用显式模式模型，但应约束“固定模式必须有文件名”等不变量，避免再造平行字段组合。
4. 决策收敛后再删除多余 EXIF 读取，确认 ImageProcessor 仍提供所需元数据，且 GPS 路径不受影响。
5. 本轮默认只处理活动调用链；legacy GUI 已封存，注明保留范围，不顺带扩张任务。

**验收。** 单张和混合品牌批量均覆盖自动/禁用/固定、无品牌、无匹配、映射改变品牌、明暗变体、样式覆盖背景。背景修正或经确认的品牌来源变更要列入预期差异，不能承诺全部像素不变。

## 4. 矩形与渲染边界的结构改进

### Q1：分离整帧编排和矩形子系统

**证据。** renderer 模块 991 行，FrameRenderer 类 744 行。矩形相关数据结构、分流、分析、绘制与蒙版约 526–527 行；其中颜色解析、蒙版、单矩形绘制是模块级函数，并非全在类内。规模和职责耦合值得处理，但不能仅凭行数定为 P0。

**执行动作。** 在 Q3 最小修复完成并留存基线后，将矩形分析和绘制收敛到有明确职责的模块，例如 `src/core/rectangle_layer.py`。renderer 保留整帧阶段顺序。原图和矩形共享的圆角蒙版放在双方都可复用的层，避免 renderer 与新模块相互导入。

统一计划要表达三种结果：

| 分类 | 如何处理 |
|---|---|
| legacy | 只在原图下方绘制 |
| 有有效层的 effect_stack | 只在原图上方绘制 |
| 禁用、无效或画布外的 effect_stack | 不绘制，不回流 legacy |

**验收。** 分类、几何和颜色解析不再由两条路径重复决定；以 Q3 修复后的版本为基线，对内置样式及异常边界逐像素比较。文件变短不是唯一指标，还需说明删除了哪些重复决策。模块名和最终行数是实现选择，不预先承诺缩至某个行数。

### Q2：用有效层对象收敛平行旗标

**证据。** `RectangleSpec`（121–148）有 16 个字段；`_analyze_rectangles`（433–622）约 190 行，反复更新 fill/stroke/blur 的 enabled、颜色、透明度、厚度等字段，绘制端再次解释这些组合。

**执行动作。** 可将填充、描边、模糊分别建模为校验后的可选层；不存在表示关闭/无效，存在时参数已满足绘制要求。保留层间规则，例如有效不透明填充会使下层模糊不可见。Q1 统一计划承担分类，不能再用层存在性倒推 legacy 身份。

**验收。** 覆盖三层组合、单层降级、描边上下限、模糊安全上限、不透明填充遮蔽模糊；有明确约束的参数只能在一个入口完成解析。不得因主函数变短就宣称总复杂度按相同比例下降。

### Q7：背景注册表查询应封装，但画布必须保留

**证据。** `renderer.py:374–375,845` 直接读取 `BackgroundFillManager.FILL_TYPES` 的 method/text_scheme。它是公开类属性，不是私有字段；问题在于 renderer 耦合注册表 schema。项目规定背景类型由管理器统一管理，并未逐字禁止读取公开表。

**执行动作。** 在管理器提供必要的语义查询，例如是否高斯；让渲染器通过接口取得结果。避免为每个字段再套一层无意义转发。

**必须保留。** `renderer.py:839–848` 创建的 fallback 是后续复制和粘贴的承载画布，不能整段删除。无扩展、无圆角的 RGB 场景可跳过高斯；RGBA、圆角和可见边框维持原有保守判定。满足原图完全覆盖前提时，占位颜色可简化。

**验收。** 实测短路分支输出与原图一致；逐项覆盖可见边框、圆角、RGBA、自定义背景和矩形自身需要模糊的情况。封存 GUI 的直读点单独记录，不强制纳入活动管线改造。

### Q8：统一解析步骤，明确调用方失败策略

**证据。** `renderer._parse_hex_or_rgb`（43–60）对十六进制解析失败返回 None、对三元序列逐项转 int；`TextRenderer._parse_color_value`（124–131）可能抛 ValueError，且不转换序列项。renderer 的 legacy 填充回退链和 `_resolve_rect_fill_color` 也重复。

**执行动作。** 收敛公共解析和填充颜色回退。先保留调用方现有错误处理；若改为统一的“返回 None / 告警跳过 / 抛错”策略，单独说明非法输入行为变化。不要把当前某个解析器当作完整校验标准，它也不等于已经覆盖色值范围和全部格式边界。

**验收。** 正常十六进制与 RGB 三元组像素不变；覆盖空值、非法十六进制、错误长度、字符串数值、越界色值及 dark/light 回退，明确每种输入的结果。

## 5. 布局原语与配置契约

### Q4：澄清“延迟夹持”和“永久豁免”

**证据。** 文字 tree_align 子孙先跳过 padding，之后由整树定位统一夹持；`renderer.py:330,482` 对矩形始终传 `defer_padding=True`，不再补做。`STYLE_GUIDE.md:260,326` 及定位修复计划的 padding 验收项明确要求矩形豁免。

**执行动作。** 改清接口/文档，或由布局阶段显式管理夹持策略；依赖树的根查找应复用有环检测的依赖分析。不要为了“修复 padding 失效”给矩形新增夹持。

**验收。** 同一矩形仍可越过安全区绘制；普通文字受夹持；文字树在整树阶段统一平移。与 Q12 的超大盒策略修复分开验收。

### Q9：九点常量和校验可适度复用

**证据。** `layout_engine.py:44–53` 两个集合相同；160–176 的校验结构相近，但 position/alignment 的语义和错误提示不同。

**执行动作。** 可共享九点值集合并保留语义别名，校验函数保留字段名和迁移说明。若抽象反而增加间接层，保留短小校验器也合理。

**验收。** 合法值、旧别名拒绝和报错字段不变；同步核对 StyleManager 的导入及消费点。

### Q10：减少几何与诊断信息的重复求值

**证据。** `_resolve_photo_reference_point` 和 `_resolve_element_anchor` 重算照片边界；`get_absolute_layout_info` 又调用同一组核心 helper 组装日志。日志当前已经复用了几何算法，问题是额外求值与组装，并非维护两份独立数学实现。

**执行动作。** 共享照片几何结果，使原始定位与诊断来自同一次求值。九点可规范成两轴值，其中单独的 `center` 必须映射为两轴中心。保留 top/bottom 与 center-left/right 的不同 outside 主轴语义及现有整数舍入。

**验收。** 九点 position × 九点 alignment、inside/outside、非对称 margin、奇偶尺寸、画布扩展和方向适配保持坐标与像素一致；日志 raw/final/clamp 与实际结果吻合。

### Q11：统一元素查找，但先保留兼容行为

**证据。** `get_element_bounds`（149–156）先精确命中，否则用双向 endswith 查找；`_calculate_relative`（592–596）为找到注册表 key 又实现一次。`author` 可误命中 `custom_author`，但**不会**按这条规则命中 `author_name`。

**执行动作。** 抽出同时能确定真实 key 的唯一查找入口，首先保持精确优先、模糊遍历顺序及坐标访问一致。之后调查模糊匹配依赖，再决定是否移除或显式化。缺失目标预注册只覆盖部分绝对根，不能作为“没人依赖模糊匹配”的证据。

**验收。** 精确命中、唯一后缀命中、多候选、缺失目标、位移传播覆盖同一个真实 key；取消匹配时另列迁移或失败行为，不能混入等价提交。

### Q12：夹持逻辑有重复，也有实质差异

**证据。** 普通盒及相对定位末尾（362–365、609–610）使用 max/min 公式；组合盒及树（581–588、714–723）使用左/上先检查、否则检查右/下的 if/elif。相对定位还会先移动组合盒，再夹持当前元素。

已实测：画布 100×100，安全区横向为 [20,80]，元素宽 80、原始 x=30。普通盒最终 x=20；同尺寸单成员 tree_align 树最终 x=0。两者相差 20px，与单成员树应同普通盒的注释不一致。

**执行动作。** 先合并确实相同的普通盒公式。超大盒应优先哪一边，先按 §2 明确策略；推荐评估统一为普通盒的左/上优先，但该选择尚未成为已确认需求。整树变化必须是所有成员同量平移，不能逐个夹持破坏相对位置。

**验收。** 小于、等于、大于安全区，单边/双边越界，单成员/多成员树，深层相对依赖均覆盖。如果采用左/上优先，反例树 x 从 0 变为 20 是预期修复差异；不能继续宣称三处原本完全相同。

### Q13：命名应体现 padding 与 margin 的不同单位

**证据。** `_calculate_padding_bounds`（122–125）把 int/float 都作为比例；`_resolve_margins`（423–426）把 float 作为比例、int 作为像素。短边 4000 时，padding 10 → 40000px，margin 10 → 10px，margin 10.0 → 40000px。样式指南和 StyleManager 的 `margin: 10` 默认配置确认这一差异是既定语义。

**执行动作。** 使用能表达单位的名字，例如比例换算与像素/比例换算分别命名。不能将二者都替换成同一种 ratio_to_px。内部已被调用前置条件排除的 None 分支可局部清理；新增非法类型或过大 padding 诊断单列行为变化。

**验收。** 单独验证解析结果，再验证定位，避免最终 padding 夹持掩盖单位差异；覆盖整数、浮点、零、负数及现有方向覆盖优先级。

### Q15：减少全画布开销，保留逐次合成语义

**证据。** `_draw_single_rectangle`（206–245）每个矩形创建全画布 RGBA 层，进行两次 convert 和一次 alpha_composite。问题是分配、转换与合成开销；这些是局部中间图，没有证据表明存在共享输出的非原子更新。

**已实测的方案限制。** 下列 1×1 反例说明“先合并透明矩形组、最后合背景”会因 8-bit 中间舍入改变像素：

| 输入 / 顺序 | RGBA |
|---|---|
| 不透明背景 | (17,83,191,255) |
| 第一矩形 | (231,31,7,2) |
| 第二矩形 | (2,219,101,127) |
| 背景逐次合两矩形 | **(11,151,146,255)** |
| 两矩形先合组再合背景 | **(10,151,145,255)** |

**执行动作。** 先评估背景只转一次 RGBA、逐矩形按原顺序合成、末尾转回 RGB，再评估局部 patch。所有替代实现需保持裁切、蒙版及量化步骤。直接把矩形 paste 到同一透明层还可能覆盖底层 alpha，不可当作顺序合成。

**验收。** 重叠半透明矩形、不同绘制顺序、圆角抗锯齿、跨画布边界和上述反例逐像素一致。再测大图耗时和峰值内存。未有基准数据前只描述开销来源，不宣称具体收益；当前执行默认不接受透明组合成造成的色阶变化。
