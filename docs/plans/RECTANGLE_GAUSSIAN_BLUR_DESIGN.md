## 1. 结论

建议第一阶段采用“复用型”方案，并把模糊算法拆成可缓存的原始模糊结果与后续着色两个阶段；精确型作为后续可选质量模式保留。矩形效果统一建模为三个独立开关，采用内描边，固定层级为“高斯模糊底层 → 纯色填充中层 → 内描边顶层”。

原因如下：

- 矩形完全位于照片内部时，基于原图生成的模糊层与最终照片坐标能够严格对齐，复用型已经能得到正确效果。
- 矩形位于照片外部时，复用当前背景模糊的“原图拉伸到画布”语义，与现有高斯模糊背景的视觉风格一致。
- 当前 33MP 样片的模糊背景端到端已有约 `2.64s` 的观测值。精确型会在背景生成后再对合成场景执行一次模糊，成本和峰值内存都明显更高。
- 当前算法函数只返回“已缩放、已增强饱和度、已叠加黑/白色”的最终背景，不能直接作为矩形模糊源。直接复用会让矩形继承背景色调，再叠加矩形颜色，产生双重着色。因此必须复用着色前的原始模糊结果，而不是复用最终背景图。
- 复用不是无条件发生：只有源图、模糊半径和算法参数一致时才能共享卷积结果。矩形半径与背景半径不同时，仍需分别计算。
- 缓存需要分为“单次渲染内复用”和“交互式多次渲染复用”两级。仅使用每次 `render_frame()` 的局部缓存，切换背景时仍会重新卷积；跨帧缓存必须由稳定的图片版本键驱动，并设置内存上限。
- 内描边使用外轮廓与内缩轮廓之差生成环形蒙版，最后合成，既不会改变矩形外部尺寸，也不会被模糊或填充覆盖。

同时确认：当前实现只有纯色背景会绕过高斯模糊；“未扩展画布但选择了高斯背景”仍会完整执行模糊，即使稍后原图会覆盖整张背景。新方案不再以“背景是否可见”作为总短路开关，而是在渲染前汇总整张输出图的高斯消费者；只有背景和所有矩形都不需要高斯结果时，才整体绕过高斯算法。

## 2. 当前实现与调用关系

### 2.1 模块职责

| 模块 | 当前职责 | 与本需求的关系 |
|---|---|---|
| `src/utils/gaussian_blur.py` | 降采样、三遍 Box Blur 近似高斯、饱和度增强、画布缩放、颜色叠加 | 应继续保持为纯算法层，不负责判断画布扩展、矩形位置或是否启用 |
| `src/utils/background_fill.py` | 根据 `FILL_TYPES` 选择纯色或高斯背景，并调用算法模块 | 仍是“背景填充”的唯一入口，但不应成为矩形填充管理器 |
| `src/core/renderer.py` | 创建背景、绘制矩形、粘贴原图、装饰、文字和 Logo | 应负责模糊需求分析、一级帧内缓存、二级缓存接入和图层编排 |
| `src/utils/layout_engine.py` | 计算画布、原图边界及矩形位置 | 可直接用于判断矩形在照片内、跨界或照片外 |
| `src/frame_styles/style_manager.py` | 加载配置和基础结构校验 | 当前不会剔除未知矩形字段，可直接把新增配置传给渲染器 |

### 2.2 当前图层顺序

```text
背景填充
  -> 自定义矩形（现有纯色矩形）
  -> 原图/原图圆角
  -> 装饰
  -> 文字
  -> Logo
```

这意味着现有矩形位于原图下方。矩形即使按 `placement: inside` 定位到照片内部，也会被随后粘贴的原图覆盖。

新增效果栈矩形若要在照片内部可见，必须位于原图上方。为避免改变已有样式，推荐拆成“旧式矩形”和“效果栈矩形”两个阶段：

```text
背景填充
  -> 旧式纯色矩形（保持原位置，兼容旧样式）
  -> 原图/原图圆角，形成 base_scene
  -> 效果栈矩形（高斯模糊底层 -> 纯色填充中层 -> 内描边顶层）
  -> 装饰
  -> 文字
  -> Logo
```

因此：

- 完全不使用新增效果字段的矩形保持当前行为和像素结果。
- 启用描边、启用高斯模糊，或显式配置 `fill.enabled` 的矩形进入新的“原图上方”效果栈。
- 同一效果栈内部固定先绘制高斯模糊，再绘制纯色填充，最后绘制内描边。
- 多个效果栈矩形仍按 key 排序；后绘制的矩形覆盖先绘制矩形。高斯层从冻结的基础场景取样，避免把前一个矩形再次模糊造成顺序依赖。

### 2.3 当前高斯模糊的启用逻辑

当前 `FrameRenderer.render_frame()` 无条件调用 `BackgroundFillManager.render()`。该方法的实际分支为：

```text
method == solid    -> Image.new()，不调用模糊
method == gaussian -> 无条件调用 apply_gaussian_blur_overlay_expansion()
```

因此当前行为如下：

| 场景 | 当前是否执行模糊 | 是否合理 |
|---|---:|---|
| 纯黑、纯白背景 | 否 | 合理 |
| 样式 `custom_bg_color` 覆盖为自定义纯色 | 否 | 合理 |
| 高斯背景 + 画布扩展 | 是 | 合理，扩展区域可见 |
| 高斯背景 + 无画布扩展 + 无原图圆角 | 是 | 不合理，结果会被原图完全覆盖 |
| 高斯背景 + 无画布扩展 + 有原图圆角 | 是 | 有必要，四角可能露出背景 |
| 高斯背景 + `expand_canvas.enabled: true` 但四边扩展量均为 0 | 是 | 不合理，实际画布没有扩展 |

`saturation_override` 只改变高斯背景的饱和度系数，不决定是否调用模糊。

## 3. 样式配置设计

推荐在每个矩形内部增加三个同级效果配置，不增加新的顶层配置：

```yaml
colors:
  custom_rect_01_light_color: [255, 255, 255]
  custom_rect_01_dark_color: [20, 20, 20]
  custom_rect_01_stroke_light_color: [235, 235, 235]
  custom_rect_01_stroke_dark_color: [35, 35, 35]

layout:
  rectangles:
    rect_01:
      width_ratio: 0.85
      height_ratio: 0.10
      placement: inside
      position: bottom
      alignment: center
      margin_bottom: 0.03

      # 新增：纯色填充开关；现有 opacity 继续控制该层透明度。
      fill:
        enabled: true
      opacity: 0.25

      # 新增：矩形底层的高斯模糊。
      gaussian_blur:
        enabled: true
        radius: 80

      # 新增：矩形顶层的内描边。
      stroke:
        enabled: true
        radius_ratio: 0.005
        opacity: 0.90

      corner_radius:
        top_left: 0.01
        top_right: 0.01
        bottom_left: 0.01
        bottom_right: 0.01
```

字段语义：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `fill.enabled` | `bool` | `true` | 是否绘制现有纯色填充；缺失时保持旧样式的默认开启语义 |
| `opacity` | `float` | `1.0` | 保持现有语义，只控制中间纯色填充，不改变模糊或描边透明度 |
| `gaussian_blur.enabled` | `bool` | `false` | 是否绘制底部的模糊层 |
| `gaussian_blur.radius` | `int/float` | `200` | 全分辨率等效模糊半径，算法内部按工作分辨率同比缩放 |
| `stroke.enabled` | `bool` | `false` | 是否绘制顶部内描边层 |
| `stroke.radius_ratio` | `float` | `0.005` | 描边厚度相对原图短边的比例；采用内描边，不改变矩形外部尺寸和定位 |
| `stroke.opacity` | `float` | `1.0` | 描边独立透明度，不复用填充 `opacity` |
| `corner_radius` | `dict` | 无 | 定义矩形外轮廓圆角；描边内轮廓按描边厚度自动内缩 |

这里将需求中的“描边半径”解释为描边厚度。配置名使用 `radius_ratio`，明确其按 `reference_side` 缩放，避免与以输出像素表示的 `gaussian_blur.radius` 混淆。描边采用内描边：现有 `width_ratio`、`height_ratio` 和定位结果继续描述矩形外轮廓，开启描边不会扩大矩形、改变锚点或额外越过画布边界。

描边颜色使用独立的明暗自适应键：

```text
custom_{rect_name}_stroke_dark_color
custom_{rect_name}_stroke_light_color
```

解析优先级为“当前明暗方案的描边色 → 另一方案的描边色 → 当前填充色 → 另一方案的填充色”。这样旧样式只需打开描边也能获得结果，而新样式可以独立控制描边与填充颜色。

兼容和容错规则：

1. `fill`、`stroke` 和 `gaussian_blur` 全部缺失：走原有矩形路径，输出应与旧版本像素一致。
2. `fill.enabled` 缺失时默认为 `true`；显式设为 `false` 时不解析、不要求填充颜色。
3. `stroke.enabled` 和 `gaussian_blur.enabled` 缺失时均默认为 `false`。
4. 启用模糊且启用填充：先绘制完整模糊结果，再按 `opacity` 叠加颜色，实现“模糊着色”。
5. 启用模糊但关闭填充或缺少有效填充色：允许只显示模糊。
6. 开启描边但未配置独立描边色：按上述优先级回退到填充色；仍无有效颜色时只跳过描边层，不影响模糊或填充层。
7. 每层单独验证和降级。某一层无效不能导致整个矩形被跳过；只有三层都关闭、无效或完全不可见时才跳过矩形。
8. `opacity: 0`：纯色填充透明；`opacity: 1`：纯色填充完全覆盖矩形区域，可跳过其下方的模糊计算；顶层描边不受影响。
9. `gaussian_blur.radius` 必须为有限正数。建议实现时设资源安全上限并在超限时 warning；上限应通过实际样片基准确定，不建议静默截断。
10. `stroke.radius_ratio` 必须为有限正数。换算后的像素厚度若达到矩形短边的一半，应 warning 并限制到仍能保留至少 1px 内容区的最大值。
11. `fill`、`stroke`、`gaussian_blur`、`width_ratio`、`height_ratio`、`opacity`、`corner_radius` 和 `name` 都属于矩形专用字段，构造定位配置时必须剔除，不能传入定位引擎。

不建议把模糊半径命名为顶层 `blur_radius`：结构化字段更容易扩展质量模式、边缘策略等参数，也不会与背景填充的 `blur_radius` 混淆。

### 3.1 效果栈模式与旧式模式

为同时支持填充开关和旧样式兼容，矩形分流规则如下：

```text
legacy_mode =
    fill 字段缺失
    and stroke.enabled != true
    and gaussian_blur.enabled != true

effect_stack_mode = not legacy_mode
```

- `legacy_mode`：仍在原图下方绘制原有纯色矩形。
- `effect_stack_mode`：在原图上方按“模糊 → 填充 → 内描边”合成。
- 仅写入 `stroke.enabled: false` 或 `gaussian_blur.enabled: false` 不会把旧矩形意外迁移到原图上方。
- 显式写入 `fill.enabled` 表示样式作者选择了新的效果栈语义，即使另外两层关闭也是如此。
- 新建效果栈样式时建议始终显式写出三个 `enabled`，避免 `fill.enabled` 的兼容默认值掩盖已开启的模糊层。

### 3.2 八种开关组合

| 描边 | 高斯模糊 | 填充 | 结果 |
|---:|---:|---:|---|
| 关 | 关 | 关 | 不绘制矩形 |
| 开 | 关 | 关 | 仅显示顶层内描边环，内部显示原场景 |
| 关 | 开 | 关 | 仅显示模糊内容 |
| 关 | 关 | 开 | 仅显示纯色填充 |
| 开 | 开 | 关 | 完整矩形模糊 + 顶层内描边 |
| 开 | 关 | 开 | 完整矩形纯色填充 + 顶层内描边 |
| 关 | 开 | 开 | 模糊底色 + 中层颜色着色 |
| 开 | 开 | 开 | 模糊底色 + 颜色着色 + 顶层内描边 |

## 4. 两种计算方案评估

### 4.1 方案 A：复用型（推荐首期）

#### 计算语义

1. 矩形完全位于 `original_bounds` 内：使用与原图相同尺寸、相同坐标系的模糊层，按照片局部坐标截取。
2. 矩形跨越照片边界或完全位于照片外：使用与画布相同尺寸的模糊层，按画布坐标截取。
3. 画布尺寸模糊层延续现有背景语义：先模糊原图，再缩放到完整画布；它不是“背景与照片合成后再模糊”。

矩形分类使用未裁切矩形盒和原图盒的包含关系：

```text
inside = rect.left   >= photo.left
     and rect.top    >= photo.top
     and rect.right  <= photo.right
     and rect.bottom <= photo.bottom
```

绘制前还要计算矩形与画布的交集；完全在画布外的矩形直接跳过，不能触发任何模糊计算。

#### 真正可复用的内容

当前算法顺序为：

```text
原图 -> 工作尺寸 -> Box Blur -> 饱和度增强 -> 目标画布尺寸 -> 黑/白叠色
```

应拆为：

```text
共享阶段：原图 -> 工作尺寸 -> Box Blur

背景分支：共享结果 -> 背景饱和度增强 -> 画布尺寸 -> 背景黑/白叠色
矩形分支：共享结果 -> 原图尺寸或画布尺寸 -> 矩形蒙版 -> 矩形颜色叠色
```

这样既能共享最昂贵的卷积，也能保证：

- GUI 的“背景增强”只影响背景，不意外改变矩形内容。
- 背景黑/白覆盖色不会污染矩形的模糊底层。
- 矩形颜色和 `opacity` 只执行一次，不发生双重着色。

缓存必须是单次 `render_frame()` 生命周期内的局部缓存，不能使用无界全局缓存。推荐缓存键至少包含：

```text
(source_kind, source_size, radius, algorithm_version)
```

其中 `source_kind` 至少区分 `photo` 和后续精确型的 `base_scene`。同一源和同一半径的多个矩形共享一次卷积；不同目标尺寸只产生廉价得多的缩放结果。

#### 优点

- 同半径高斯背景和矩形可共享卷积结果。
- 多个同半径矩形只计算一次模糊。
- 照片内矩形坐标准确。
- 保持现有背景拉伸风格，改动范围可控。
- 易于按需求懒加载，没有可见模糊区域时可以零计算。

#### 局限

- 跨界矩形使用“原图拉伸到画布”的模糊源，照片边界两侧并不是对最终场景的连续采样；跨界处可能出现纹理或比例跳变。
- 纯色背景下，照片外矩形显示的是拉伸后的照片模糊，而不是对纯色背景本身模糊。这是有内容的磨砂设计，但需要在用户文档中明确。
- 矩形半径与背景半径不同时不能复用卷积。
- 如果直接复用当前最终背景图，会继承背景叠色，效果错误；必须先完成算法阶段拆分。

### 4.2 方案 B：精确型

#### 计算语义

先生成基础场景：

```text
背景填充 + 旧式纯色矩形 + 原图/原图圆角 = base_scene
```

然后按半径对冻结的 `base_scene` 进行第二次模糊，矩形从该模糊场景中截取同坐标区域，最后叠加自身颜色。

多个矩形半径相同时共享一张 `base_scene` 模糊结果；不同半径各计算一次。模糊源不包含任何已绘制的高斯模糊矩形，避免递归模糊和绘制顺序改变采样结果。

#### 优点

- 矩形内看到的就是其下方真实场景的模糊版本。
- 跨越照片与背景边界时，边缘和内容连续，磨砂玻璃效果最自然。
- 不需要按“照片内/跨界/照片外”选择不同源，语义简单统一。

#### 缺点

- 即使背景已经完成一次高斯模糊，仍需对合成场景执行第二次模糊。
- 不同半径会线性增加卷积次数和缓存图数量。
- 当前实现会把目标尺寸图像转为多个全画布 `float32` 数组；精确型更容易抬高峰值内存。
- 对只位于照片内部的小矩形而言，全场景二次模糊的收益有限、成本过高。

### 4.3 选型对比

| 维度 | 方案 A：复用型 | 方案 B：精确型 |
|---|---|---|
| 照片内部效果 | 准确 | 准确 |
| 跨照片边界效果 | 近似，可能有纹理跳变 | 最自然、连续 |
| 复用现有背景卷积 | 半径一致时可以 | 通常不能 |
| 纯色背景 + 模糊矩形 | 按需模糊原图 | 模糊最终纯色背景与照片场景 |
| 多矩形同半径 | 一次卷积 | 一次场景卷积 |
| 性能与内存 | 较优 | 较高 |
| 首期实现风险 | 中 | 中高 |
| 推荐用途 | 默认模式、批量处理 | 高质量输出、明显跨界的大矩形 |

推荐落地顺序：

1. 首期只对外提供 `enabled` 和 `radius`，内部固定采用方案 A。
2. 算法和缓存接口预留 `source_kind=base_scene`，避免未来实现方案 B 时再次重构。
3. 若真实样式证明跨界伪影不可接受，再增加可选字段，例如 `quality: fast | precise`；不建议在尚无基准和样片前立即扩大公开配置面。

## 5. 推荐的渲染架构

### 5.1 需求分析阶段

`FrameRenderer` 在生成背景前先解析矩形几何和效果，形成内部 `RectangleSpec` 列表。该阶段完成：

- 尺寸、位置、画布交集计算；
- 旧式模式/效果栈模式分流；
- 填充、描边、模糊三个开关及各自参数校验；
- 填充色、描边色和各自不透明度解析；
- 外轮廓、内轮廓和顶层描边环蒙版计算；
- 矩形属于照片内还是跨界/照片外；
- 按来源和半径汇总模糊需求；
- 汇总背景与全部矩形后生成全图级 `gaussian_required` 结论。

这样可以在执行任何高成本运算前排除无效、不可见或被完全不透明颜色覆盖的模糊请求。

### 5.2 两级模糊缓存

建议在 `src/core` 增加两级缓存。缓存状态不放入纯算法模块，也不使用无容量限制的进程级全局缓存。

#### 一级：单次渲染缓存

`RenderBlurCache` 的生命周期只覆盖一次 `render_frame()`，职责是：

- 同一帧内的背景和多个矩形共享原图卷积；
- 多个同半径矩形只计算一次；
- 缓存由 `PreparedBlur` 派生的原图尺寸/画布尺寸结果；
- 渲染结束后释放全尺寸目标图，避免长期占用大图内存。

一级缓存解决的是“同一次输出内重复计算”，不能解决切换背景后再次调用 `render_frame()` 的重复计算。

#### 二级：跨渲染原图缓存

`PreparedBlurLRU` 跨多次 `render_frame()` 保存着色前、缩放到目标尺寸前的 `PreparedBlur`，只缓存 `source_kind=photo` 的工作分辨率卷积结果。它应由交互会话持有，例如样式编辑器页面或图片处理页面，而不是由算法模块全局持有。

二级缓存解决：

- 同一图片切换不同背景颜色或背景透明度时复用卷积；
- 同一图片在高斯背景与纯色背景之间来回切换后，再次选择高斯背景时复用；
- 修改文字、Logo、填充、描边、矩形位置等不改变原图像素的样式参数时复用；
- 切换到另一张图片再切回时，在缓存尚未淘汰的情况下复用。

二级缓存只保存原始卷积结果，不保存全尺寸画布、背景叠色结果或最终合成图。建议采用按 `nbytes` 计量的 LRU，默认预算约 `64 MiB`；超出预算时从最久未使用项开始释放。工作长边上限为 1200 时，一张方形 `float32 RGB` 工作图的理论上限约为 `16.5 MiB`，该预算可容纳少量图片/半径组合而不会无界增长。

职责边界：

```text
gaussian_blur.py
  只做：工作尺寸计算、卷积、饱和度、缩放、叠色

RenderBlurCache
  只做：单次渲染内按源和半径懒计算、派生尺寸缓存、统计命中

PreparedBlurLRU
  只做：跨渲染保存受内存预算约束的 photo 原始卷积结果

BackgroundFillManager
  只做：解释背景类型，并向资源提供器请求所需图像

FrameRenderer
  只做：判断是否需要、选择照片源/画布源、图层合成
```

算法层建议提供等价于以下职责的接口，具体命名可在实现时调整：

```python
prepare_gaussian_blur(image, radius) -> PreparedBlur
render_prepared_blur(prepared, target_size, saturation=1.0) -> Image.Image
apply_color_overlay(image, color, opacity) -> Image.Image
```

`PreparedBlur` 表示着色前、目标尺寸缩放前的工作分辨率结果。它使原图尺寸与画布尺寸两个分支共享同一次卷积。

### 5.3 调用链审计与缓存生命周期

当前代码还没有高斯模糊缓存，所有高斯路径都会重新计算。即使按前述方案只增加一级缓存，以下调用仍会发生跨帧重复计算：

| 调用场景 | 当前调用特征 | 仅一级缓存的结果 |
|---|---|---|
| 样式编辑器切换背景 | `_on_preview_bg_changed()` 立即再次调用 `_render_preview()` | 重新卷积 |
| 样式编辑器修改任意配置 | 300ms 去抖后再次调用 `_render_preview()` | 重新卷积 |
| 样式编辑器切换横/竖图 | 选择另一张样本图并重新渲染 | 新图片应重新卷积 |
| 主处理页切换背景下拉框 | 仅改变控件，不会立即生成结果 | 此刻不计算 |
| 主处理页再次点击“生成相框” | 每次新建 `ImageProcessor` 和 `FrameRenderer` | 同一图片也会重新卷积 |
| 批量处理 | 复用一个 `ImageProcessor`，但逐张输入不同图片 | 每张重新卷积是正确行为 |

样式编辑器的 `_get_sample_image()` 每次返回 `.copy()`，因此不能用 `id(image)` 作为跨帧缓存键；主处理页每次生成的输入临时文件路径也不同，因此不能用临时路径作为图片身份。

推荐接口关系：

```text
交互页面
  持有 PreparedBlurLRU
  持有可复用 ImageProcessor / FrameRenderer
  为每张源图提供稳定 source_cache_key
        |
        v
render_frame(..., source_cache_key, prepared_blur_cache)
  创建本次 RenderBlurCache
  RenderBlurCache 先查二级 LRU，未命中才调用 prepare_gaussian_blur()
```

稳定键不能通过每次对 `image.tobytes()` 重新哈希生成，否则会引入一次全图扫描。推荐来源：

- 样式编辑器样本图：`(preview_asset, orientation, asset_revision)`；横图和竖图使用不同键。
- `FileItem`：导入时对已在内存中的 `file_bytes` 计算一次摘要并保存，后续生成直接复用。
- CLI 文件：可使用 `(resolved_path, size, mtime_ns)`；若要求抵御元数据未变但内容变化的极端情况，再选择一次性内容摘要。

完整缓存键至少包含：

```text
(
    source_cache_key,
    normalized_image_size,
    normalized_image_mode,
    preprocessing_version,
    blur_radius,
    gaussian_algorithm_version,
)
```

`preprocessing_version` 覆盖 EXIF 转正、ICC 转换和超尺寸缩放规则。背景类型、背景叠色、背景透明度、饱和度、目标画布尺寸和矩形位置不进入 `PreparedBlur` 键，因为这些步骤发生在原始卷积之后。这样切换背景时可以命中缓存，同时仍会重新执行必要且较轻的饱和度、缩放和叠色。

失效规则：

- 切换到不同图片：因 `source_cache_key` 不同而未命中，这是必要计算，不是重复计算。
- 切回旧图片：若条目仍在 LRU 内则命中，否则重新计算。
- 原图内容、EXIF 方向、ICC 处理结果或预处理尺寸变化：必须更换 source key 或 preprocessing version。
- 模糊半径或算法版本变化：必须重新卷积。
- 背景颜色、背景透明度、饱和度或画布扩展变化：复用原始卷积，只重新派生当前帧结果。
- 填充开关/颜色/透明度、描边开关/颜色/厚度变化：复用原始卷积，只重建矩形蒙版和效果层。
- 图片从胶片栏移除时可按 source key 主动清理；页面关闭时清空页面级缓存。

精确型的 `source_kind=base_scene` 依赖背景、画布、圆角和旧式矩形。首期只允许它使用一级缓存，不进入跨帧 LRU；否则切换背景时必须构造复杂的完整场景指纹，容易错误复用旧场景。精确型切换背景后重新卷积属于正确失效。

为让主处理页真正获得跨生成复用，应把当前“每次点击都创建 `ImageProcessor`”调整为页面级可复用实例，并把 `FileItem` 的稳定 source key 传递到渲染器。批量处理保持只使用一级缓存，避免连续处理不同照片时让二级缓存产生无效内存驻留。

### 5.4 全图高斯需求与统一短路

短路条件应位于整帧渲染级，而不是绑定在背景分支上。渲染器先收集所有可能消费高斯结果的区域：

```text
background_gaussian_required =
    背景类型为 gaussian
    and 最终输出存在可见背景像素

rectangle_gaussian_required =
    至少一个开启 gaussian_blur 的有效矩形与画布相交
    and 存在非空的内层内容区
    and 其模糊结果不会被启用且 opacity=1 的有效颜色填充完全覆盖

gaussian_required =
    background_gaussian_required
    or rectangle_gaussian_required
```

执行规则：

1. `gaussian_required == false`：整帧不创建 `RenderBlurCache`，不进入 `gaussian_blur.py` 的任何高斯计算接口。
2. `gaussian_required == true`：创建每帧懒加载缓存，但只计算需求表中实际出现的 `(source_kind, radius)`。
3. 背景是否可见只负责判断背景是不是一个有效消费者，不能覆盖矩形的高斯需求。
4. 即使背景为纯色或高斯背景最终被原图完全遮挡，只要存在有效的高斯模糊矩形，全图仍必须进入高斯路径。
5. 即使用户选择了高斯背景，只要背景没有可见像素且不存在有效高斯矩形，全图仍可统一短路。

“最终输出存在可见背景像素”可按以下几何条件判断：

```text
original_bounds != (0, 0, canvas_width, canvas_height)
or 原图存在有效圆角切除
or 输入图仍可能包含透明像素
```

注意应比较最终几何，而不是只检查 `expand_canvas.enabled`，因为开关可能为 true 但四边扩展均为 0。输入图在标准 `ImageProcessor` 流程中已转换为 RGB；若 `FrameRenderer` 仍允许外部直接传入 RGBA，建议保守地视为背景可能可见，或明确收紧渲染器输入契约。

### 5.5 三层图层与蒙版合成

#### 蒙版几何

内描边位于最上层。效果栈使用外轮廓蒙版和内轮廓覆盖率：

```text
outer_mask      = 配置宽高与 corner_radius 生成的最终组裁切蒙版
inner_coverage  = 外轮廓向内收缩 stroke_px 后的内部覆盖率
stroke_coverage = 1.0 - inner_coverage
```

内轮廓几何：

```text
inner_box = (stroke_px, stroke_px,
             width - stroke_px, height - stroke_px)
inner_corner_radius[corner] = max(
    outer_corner_radius[corner] - stroke_px, 0)
```

这种内描边模型有三个优点：矩形锚点和外部尺寸不变、不会因开关描边额外越界、顶层描边不会被填充或模糊遮挡。

实现时可复用 `_rounded_corner_mask()` 两次：第一次生成外轮廓；第二次按内缩后的宽高和圆角生成较小蒙版，再粘贴到外轮廓坐标中。`stroke_coverage` 只描述矩形组内部的描边环，外边缘抗锯齿统一交给最终 `outer_mask`，防止同一 alpha 在描边层和组裁切时被乘两次。`stroke_px = max(1, round(reference_side * radius_ratio))`，前提是配置值大于 0；超过几何上限时按容错规则 warning 并限制。

#### 固定合成顺序

对每个效果栈矩形先在局部、无圆角裁切的 RGB patch 内构建内容，再只合成到画布一次：

1. **选择内容底图**：高斯开启时使用模糊 patch；否则使用当前输出在矩形位置的 underlay patch。
2. **高斯模糊底层**：高斯 patch 成为整个矩形区域的内容底图。
3. **纯色填充中层**：在内容底图上按 `opacity` 混合填充色。
4. **内描边顶层**：按 `stroke_coverage × stroke.opacity` 在内容 patch 上混合描边色。
5. **单次组裁切**：最后使用 `outer_mask` 将完整效果栈合成到当前输出。

三个开关只决定对应步骤是否执行，不改变层级顺序。不要把填充 `opacity` 同时乘到模糊层，否则 `opacity: 0.25` 会变成“25% 模糊 + 25% 着色”，无法得到稳定的磨砂底层。

采用“局部 patch 内混合、最终只裁切一次”的原因是：如果模糊、填充和描边分别携带同一个抗锯齿外轮廓逐层 `alpha_composite`，边缘 alpha 会反复参与计算，产生暗边、颜色泄漏或透明度平方。该模型也保证有效填充 `opacity: 1` 时可以安全跳过模糊——包括抗锯齿边缘在内，最终组内容已经完全由填充色决定。

模糊采样仍来自冻结的 `base_scene` 或原图缓存，不把同一矩形的填充和描边颜色卷入模糊源。否则颜色会在模糊结果内产生渗漏，也会破坏原图卷积缓存的独立性。

矩形可能为负坐标或超出画布。应先计算画布交集，再以相同偏移同步裁切：

- `stroke_coverage`；
- `outer_mask`；
- 模糊源 patch；
- 当前输出 underlay patch；
- 最终效果栈 patch。

所有层必须使用相同裁切坐标，避免描边、圆角、模糊和填充错位。

现有 `_draw_single_rectangle()` 继续服务旧式矩形，确保历史输出不变。效果栈应使用新的 `_draw_rectangle_effect_stack()`（名称可调整），不要在旧函数中堆叠大量条件。最终 patch 的透明度只由 `outer_mask` 写入一次；延续现有约束，不能在 `paste()` 时再次传入同一 alpha 作为 mask，否则透明度会被平方。

## 6. 全图高斯需求与计算矩阵

方案 A 下，先得出全图是否需要高斯算法，再按来源与不同半径决定实际卷积次数：

| 背景/矩形场景 | 全图 `gaussian_required` | 预期卷积次数 |
|---|---:|---:|
| 纯色背景，无模糊矩形 | false | 0 |
| 高斯背景，但背景完全不可见，无模糊矩形 | false | 0 |
| 高斯背景且背景可见，无模糊矩形 | true | 1 |
| 纯色背景，一个或多个同半径模糊矩形 | true | 1 |
| 高斯背景不可见，但存在有效模糊矩形 | true | 按矩形所需半径计算 |
| 高斯背景可见，矩形与背景半径相同 | true | 1，共享 |
| 高斯背景可见，矩形与背景半径不同 | true | 2 |
| 多个矩形有 N 个不同半径，背景不共享 | true | N |
| 所有模糊矩形均完全位于画布外，背景不需要高斯 | false | 0 |
| 所有模糊矩形均被 `opacity: 1` 的颜色完全覆盖，背景不需要高斯 | false | 0 |

方案 B 下，每个不同矩形半径需要一次 `base_scene` 模糊；若背景本身也使用高斯并可见，背景模糊另计。

三个矩形效果层还应各自短路：

| 条件 | 处理 |
|---|---|
| `fill.enabled == false` 或 `opacity <= 0` | 不创建填充颜色层 |
| 填充已启用、颜色有效且 `opacity >= 1` | 矩形模糊层完全不可见，不为该矩形登记高斯需求 |
| `stroke.enabled == false` 或 `stroke.opacity <= 0` | 不创建内外蒙版差和描边颜色层 |
| `stroke.radius_ratio > 0` 但换算后不足 1px | 使用 1px 描边，避免开关开启却无视觉结果 |
| 高斯关闭，仅描边和/或填充开启 | 不触发任何高斯算法或缓存访问 |
| 三层全部关闭、无效或不可见 | 整个矩形跳过，不创建全画布 RGBA 临时层 |

### 样式编辑器的现有缺口

当前 `StyleConfigFormData` 没有 `rectangles` 数据模型，`to_yaml_dict()` 和 `from_yaml_dict()` 也都不保留矩形。也就是说，用 PySide6 样式编辑器加载并再次保存现有 `FrameBar` 样式时，`layout.rectangles` 及其 `custom_rect_*` 颜色存在被丢弃的风险。这不是本需求新引入的问题，但会直接影响新字段的可维护性。

建议二选一：

1. 完整方案：新增 `RectangleConfig`、矩形配置区块和颜色编辑能力，包含填充、描边、高斯模糊三个开关，以及描边厚度、描边透明度和模糊半径。
2. 最小兼容方案：表单模型保留未被 UI 识别的原始字段，保存时回写 `layout.rectangles` 和 `custom_rect_*` 颜色，先保证不丢配置。

若本期不做样式编辑器 UI，至少应实现第 2 项，并在用户文档中注明高斯矩形通过 YAML 手工配置。若新增 GUI 区块，必须遵循项目对 `ExpandGroupSettingCard` 的尺寸调整和 `addGroupWidget()` 约定。

## 9. 验收方案

项目当前没有测试框架，因此实现阶段采用直接可执行的验证脚本、固定样片输出和语法检查，不引入 pytest。

### 9.1 兼容性

- 所有未配置 `fill`、`stroke`、`gaussian_blur` 新效果字段的内置样式输出与修改前保持一致。
- `FrameBar` 的旧式颜色矩形仍位于原图下方。
- 旧 YAML、JSON、TOML 样式均可加载。

### 9.2 功能矩阵

- 照片内、照片外、跨照片边界三种位置。
- 直角和四角独立圆角。
- 无颜色、`opacity=0`、`0.25`、`1.0`。
- 描边、模糊、填充的八种开关组合，确认固定层级为“模糊 → 填充 → 内描边”。
- 描边独立颜色、回退到填充颜色、独立透明度和最小 1px 厚度。
- 描边厚度接近矩形短边一半时的 warning、上限限制和剩余内容区。
- 纯色背景、自定义纯色背景、高斯背景。
- 单矩形、多个同半径矩形、多个不同半径矩形。
- 横图、竖图、无扩展画布、零值扩展、真实扩展画布。
- 负坐标、部分超出画布、完全超出画布。

### 9.3 性能与短路

- 用 DEBUG 计数或可注入计数器确认：全图没有有效高斯消费者时，`gaussian_required=false`，不会创建缓存或触发卷积。
- 确认背景不可见但存在有效模糊矩形时，`gaussian_required=true`，矩形模糊仍正常计算。
- 高斯背景与矩形同半径时只触发一次原图卷积。
- 完全不可见矩形不触发卷积。
- 仅描边、仅填充、描边加填充均不得触发高斯算法。
- 高斯开关开启但被有效的全不透明填充完全覆盖时，不得为该矩形触发高斯算法。
- 同一预览图在多个同半径高斯背景之间切换时，第二次及后续渲染命中二级缓存，卷积计数不增加。
- 同一预览图从高斯背景切换到纯色、再切回原高斯背景时，在 LRU 未淘汰的情况下命中缓存。
- 横图切换为竖图时必须未命中；切回横图时，在 LRU 未淘汰的情况下命中。
- 主处理页对同一 `FileItem` 使用不同背景重复生成时，同半径原图卷积可复用。
- 批量处理不同文件时不得因尺寸或文件名相同而错误命中。
- 修改 source key、预处理版本、半径或算法版本时必须未命中。
- 精确型切换背景时必须重新计算 `base_scene` 模糊，不能命中旧背景场景。
- 记录 1200×800 预览图、6000×4000 样片以及现有 7008×4672 基准样片的耗时和峰值内存。
- 将方案 B 的二次模糊作为对照，确认其视觉收益是否值得开放为配置。

### 9.4 必需检查

- 对所有修改过的 `.py` 文件执行：`python -m py_compile <files...>`。
- GUI 预览确认开关变化会触发重绘，且不会阻塞到不可接受程度。
- 打包环境确认未引入新的资源路径或依赖；本功能不应绕过 `app_paths.py`，也不需要新增资源文件。

## 10. 实施顺序

1. 先拆分 `gaussian_blur.py` 的算法阶段，保持现有背景输出像素行为不变。
2. 引入一级每帧懒加载缓存，让现有高斯背景改为从缓存取结果。
3. 增加全图高斯需求分析与统一短路，并用日志验证背景和矩形消费者的组合场景。
4. 引入矩形内部规格模型，解析填充、描边、高斯模糊三个开关并完成旧式/效果栈分流。
5. 完成照片内复用路径和跨界/照片外的画布尺寸路径。
6. 实现外轮廓、内轮廓、描边环蒙版，以及“模糊 → 填充 → 内描边”的固定合成顺序。
7. 增加 `opacity == 1` 的模糊可见性优化及各层独立降级。
8. 增加有界二级 `PreparedBlurLRU`、稳定 source key 及 GUI 生命周期接入。
9. 补齐模板、样式指南、开发文档和样式编辑器的字段保留。
10. 用固定样片完成八种开关组合、视觉、两级缓存命中、失效、性能和 `py_compile` 验收。

## 11. 风险与待评审项

- **跨界视觉定义**：方案 A 的画布源是拉伸原图的模糊背景，不是最终场景。若产品要求严格的磨砂玻璃语义，应直接选择方案 B。
- **半径默认值**：本文沿用现有背景默认值 `200` 以利于共享，但矩形通常面积更小，实际视觉可能更适合较低默认值。应通过样片评审最终确定。
- **效果栈层级迁移**：显式配置 `fill.enabled` 会让该矩形从旧式“原图下方”路径进入“原图上方”效果栈。这是支持照片内三层效果的必要新语义，模板和样式指南必须明确提示。
- **描边术语**：本文将“描边半径”定义为相对原图短边的内描边厚度，并将内描边固定在最上层；若未来需要外描边，应增加独立位置模式，不能复用当前字段静默改变几何。
- **缓存键正确性**：source key 过宽会错误复用其他图片，过窄会导致无效重复计算。禁止使用临时路径或每次变化的 PIL 对象身份作为跨帧键。
- **缓存内存**：二级缓存必须按实际字节数限制并采用 LRU；不得长期缓存全分辨率画布或让 `PreparedBlur` 间接持有原始大图。
- **样式编辑器范围**：只支持 YAML 运行时，还是同时提供 GUI 编辑，是实施排期需要明确的范围；无论如何都必须先保证 GUI 保存不丢字段。
- **文档基线缺口**：仓库当前未发现 `project_master_spec.json`。实现前若该文件位于其他分支或外部位置，应补充审阅，以确认底层规范没有额外的图层、性能或配置兼容要求。
