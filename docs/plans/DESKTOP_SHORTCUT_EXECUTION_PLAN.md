## 1. 已确认需求与交付范围

用户已确认：仅 Windows 便携版启动图形界面时，检查桌面是否有快捷方式，没有则自动添加。

- 源码 GUI、非 Windows GUI、CLI 单张/批量、帮助命令不触发。
- 检查当前用户桌面和公共桌面，只向当前用户桌面写入。
- 自动创建 `MiLecFrame.lnk`；用户删除后，下次符合条件的启动重新创建。
- 不新增设置开关、CLI 参数、安装器或管理员权限要求。
- 本期包括去重、失效的受管快捷方式修复、异常不阻塞启动。
- 照片元数据标识是另一项独立功能，不是本方案的前置依赖。

以上触发范围是用户确认项；命名、去重、修复与技术选型是本方案制定的执行规则。

当前接入点为 `src/gui_pyside/app.py::run_pyside_app()`：主窗口 `show()` 后、`app.exec()` 前调度。`src/main.py::main()` 同时服务 GUI 与 CLI，不能在该共同入口无条件执行维护。复用 `src/utils/app_paths.py` 的环境和路径工具。

## 2. 行为规则

### 2.1 触发时机与启动体验

执行条件必须同时满足：

1. `sys.platform == 'win32'`。
2. `app_paths.is_frozen()` 为真。
3. 当前进入 `run_pyside_app()` 图形界面启动流程。

主窗口显示后投递一次后台任务，检查和创建均不占用 GUI 主线程。`QTimer.singleShot()` 只能用于调度，不能在其回调中同步等待外部进程。每个 GUI 进程只调度一次；重复启动和多进程并发另由文件检查与写入保护处理。

后台任务持有明确的生命周期，不得出现 GUI 退出时销毁仍在运行的 QThread。若采用外部进程，设置超时并在超时后终止、回收；窗口关闭不等待无限期操作。默认建议总超时 5 秒，实施时以实测调整。

### 2.2 桌面定位

- 使用 Windows Known Folder 获取当前用户桌面和公共桌面的实际路径，支持用户重定向、中文路径、空格以及 OneDrive 桌面。
- 不拼接 `%USERPROFILE%\\Desktop`，不通过本地化显示名称推测目录。
- 当前 EXE 使用 `sys.executable` 的绝对路径；工作目录使用 `get_app_dir()`。
- 桌面路径不存在、不可访问或获取失败时记录原因并跳过，不创建一个猜测出来的桌面目录。
- 公共桌面仅用于检查，不修改其中的文件，也不触发权限提升。

### 2.3 判断“已有快捷方式”的规则

不能仅依据文件名或者图标外观判断，必须读取 `.lnk` 的目标和启动参数。

| 发现的状态 | 行为 |
| --- | --- |
| 用户桌面或公共桌面有指向当前 EXE、无 CLI 处理参数的有效快捷方式 | 视为已有入口，保持原文件，包括用户改过的名称 |
| 指向当前 EXE 但用于执行 CLI 批处理的快捷方式 | 不视为 GUI 入口，保留并继续查找 |
| 本程序创建的快捷方式已失效，且能确认归属 | 在用户桌面将其修复为指向当前 EXE |
| 旧版本快捷方式仍有效，目标不是当前 EXE | 保留，不擅自切换其目标；如当前版本没有入口，则使用无冲突名称创建 |
| 同名文件、目录或快捷方式属于其他程序 | 不覆盖，使用无冲突名称 |
| 快捷方式损坏或无法读取，无法确认归属 | 保留并记录，继续检查其他候选项 |
| 未找到可用 GUI 入口 | 创建新的快捷方式 |

创建时在快捷方式描述中写入明确的管理标识，例如 `MiLecFrame desktop shortcut (managed)`。修复时同时检查管理标识、原目标特征及失效状态，不能仅以文件名相同作为覆盖依据。管理标识仅用于识别本程序维护的文件，不是安全认证机制。

### 2.4 新建快捷方式内容

| 属性 | 值 |
| --- | --- |
| 默认名称 | `MiLecFrame.lnk` |
| 目标 | 当前 `sys.executable` 的绝对路径 |
| 启动参数 | 空，进入默认 GUI 模式 |
| 工作目录 | `get_app_dir()` |
| 图标 | 当前 EXE 的内嵌图标，索引 0 |
| 显示方式 | 正常窗口 |
| 描述 | 包含 MiLecFrame 名称及管理标识 |

建议使用 EXE 内嵌图标，避免快捷方式额外依赖 `_internal/assets` 中的独立 ICO 路径。快捷方式自身仍是普通 `.lnk`，不是复制 EXE，也不是创建符号链接。

### 2.5 实现技术与写入保护

建议新增 `src/utils/desktop_shortcut.py`，封装资格判断、Windows 桌面定位、快捷方式检查及维护结果。

优先采用现有 Windows 能力完成，无须为此默认引入大型依赖：Python 调用 Known Folder API 获取目录；隐藏运行固定 PowerShell 脚本，通过 `WScript.Shell` 读写快捷方式。若实测环境限制该方式，再评估直接使用 Shell Link COM 接口。

- 外部进程使用明确的系统 PowerShell 路径、`-NoProfile` 和非交互模式，隐藏窗口，避免黑窗闪烁。
- 脚本内容固定，动态路径等数据通过 JSON 标准输入传入；禁止直接拼接到脚本代码中。
- 所有动态文件路径按字面路径处理，兼容单引号、空格、中文、`$` 等字符。
- 新建时先写唯一临时 `.lnk`，校验目标、工作目录和图标后再发布到最终位置。
- 使用进程间互斥及最终写入前复查，避免两个启动实例同时创建重复入口。
- 若默认名称冲突，选择 `MiLecFrame (2).lnk` 等未占用名称；下一次按目标识别，不能持续新增编号文件。
- 修复只替换明确属于本程序且已失效的用户桌面入口；替换前再次确认文件未被其他进程或用户改变。
- 所有异常统一转换为维护结果并记录日志，不向 GUI 启动流程抛出致命异常。

后台任务不执行自动 UAC 提权、不修改执行策略、不重启资源管理器。

### 2.6 结果与日志

建议结果至少区分：`skipped`、`exists`、`created`、`repaired`、`failed`，附带简短原因。不存在无需记录为失败，名称冲突后成功创建也不是失败。

- DEBUG：触发条件、检查范围、已有入口命中、冲突处理。
- INFO：成功创建或修复的路径。
- WARNING：权限不足、Shell/PowerShell 不可用、超时、快捷方式损坏等可恢复情况。
- 这些异常不弹阻断对话框、不影响照片处理，也不让 GUI 启动失败。

## 4. 确定的技术路线与模块契约

本期采用 **标准库后台线程 + subprocess + 固定 PowerShell 脚本 + WScript.Shell**。不新增 pywin32 依赖，不引入新的 GUI 控件。先在本项目实际 Windows PowerShell 5.1 环境完成最小探针，验证成功后再接 GUI。

后台线程只管理操作系统资源和记录日志，不读写任何 QWidget。GUI 只负责启动及退出通知。`subprocess` 的 `CREATE_NO_WINDOW` 用于隐藏子进程窗口；超时后必须主动结束并回收进程，单纯捕获 `TimeoutExpired` 不会自动完成回收。参考 [Python subprocess 文档](https://docs.python.org/3/library/subprocess.html)。

### 4.1 文件责任与依赖方向

| 文件 | 具体改动 | 禁止放入的逻辑 |
| --- | --- | --- |
| `src/utils/desktop_shortcut.py`（新增） | 数据模型、资格判断、路径识别、任务控制、固定脚本、结果解析 | GUI 控件、图片渲染、版本升号 |
| `src/gui_pyside/app.py` | 强引用任务对象；窗口显示后调度；退出时取消 | COM 细节、桌面枚举、同步等待 5 秒 |
| `src/utils/app_paths.py` | 复用环境、程序目录；原则上无需修改 | 重复一套资源根规则 |
| `MiLecFrame.spec` | 核查新增模块能被静态导入收集，必要时补充 | 为本功能执行 collect_all 或增加无关依赖 |
| `README.md` / `CHANGELOG.md` | 实现通过验收后说明自动创建和删除后重建行为 | 提前声明功能已经发布 |

固定脚本内置于 Python 模块，避免新增 `.ps1` 外部资源和打包路径。脚本应拆分命名清楚的小函数，保留中文设计注释；注释中的非 ASCII 字符通过脚本编码正确传输。

### 4.2 Python 接口草案

以下名称为建议接口，不是已存在的函数；实现应维持这些职责边界。

| 接口或模型 | 输入 | 返回/行为 |
| --- | --- | --- |
| `should_manage_shortcut(platform, frozen)` | 平台字符串、打包标志 | 纯布尔值；只由 GUI 入口使用 |
| `ShortcutRequest` | 当前 EXE、工作目录、用户桌面、公共桌面、请求 ID | 不可变请求；路径均为绝对路径；公共桌面可为空 |
| `ShortcutResult` | `status, reason, shortcut_path, elapsed_ms` | status 限于 skipped/exists/created/repaired/failed |
| `get_desktop_paths()` | 无 | 通过 Known Folder 返回真实路径，释放 API 分配内存；仅后台调用 |
| `run_shortcut_request(request, cancel_event)` | 请求与取消事件 | 执行脚本、处理超时、验证响应、返回结构化结果 |
| `ShortcutStartupTask.start_once()` | 无 | 幂等启动一个后台线程，重复调用不会再启动 |
| `ShortcutStartupTask.cancel()` | 无 | 标记取消；结束已注册的子进程；不无限等待 |

测试接口允许注入临时桌面、假目标 EXE 路径、脚本运行器和较短超时；这些注入只存在于内部函数，不向普通用户暴露新的 CLI 选项。

### 4.3 进程通信协议

- 用参数列表调用 PowerShell，`shell=False`，不得经 `cmd /c` 再包装。
- 使用系统目录中的 `WindowsPowerShell/v1.0/powershell.exe`；文件缺失则直接返回 `failed/powershell_unavailable`。
- 固定参数包含 `-NoLogo -NoProfile -NonInteractive -EncodedCommand`；脚本按该参数要求编码，禁止拼入用户路径。编码只解决传输，不是安全隔离。
- 标准输入为 UTF-8 JSON，读完后关闭 stdin；脚本显式设置输入/输出 UTF-8 编码，避免 PowerShell 5.1 默认编码造成中文乱码。
- JSON 至少包含 `protocol_version=1`、`request_id`、`executable`、`working_directory`、`user_desktop`、`public_desktop`、`temporary_link_path`。
- stdout 仅输出一个压缩 JSON 对象，字段与 `ShortcutResult` 对应，包含相同请求 ID；调试信息不混入 stdout。
- 非零退出码、空响应、无效 JSON、请求 ID 不匹配、未知状态统一记为失败，不能猜测创建成功。
- stderr 限制写日志的长度，不把整份脚本或环境变量打印到日志。

### 4.4 识别、锁与提交算法

1. 规范化目录和 EXE 路径进行 Windows 不区分大小写的比较。路径存在时可进一步使用文件同一性判断；不存在时不能强行调用必须成功的解析操作。
2. 以规范化用户桌面路径的 SHA-256 派生命名互斥量，名称形如 `Local\\MiLecFrame.DesktopShortcut.<digest>`。锁覆盖同一交互会话内同一桌面上的所有版本，不能以 EXE 路径分别加锁。
3. 后台在取得锁后重新枚举两个桌面当前层的 `.lnk`，不递归遍历桌面目录，不遍历其他用户目录。
4. 先查找目标为当前 EXE 且参数为空或仅空白的入口；为避免解析歧义，本期有其他参数的链接一律不作为默认 GUI 入口。
5. 找不到时再查修复候选：用户桌面、描述精确匹配管理标识、旧目标文件名为 MiLecFrame.exe、目标确认不存在。访问被拒绝、网络不可达不能当作“确认不存在”。
6. 多个候选时按规范化文件名稳定排序，最多修复一个，不删除其余文件。
7. 没有修复候选则选择第一个空闲名称；预设最多探测 100 个编号，耗尽返回 `failed/name_exhausted`，不无限扫描。
8. 在用户桌面写入本次请求唯一临时 `.lnk`；重新读取并核对目标、参数、目录、图标、描述。
9. 新建发布采用“不覆盖已存在文件”的重命名；发生冲突就重新检查，在剩余时间内选下一个名称，不能强制覆盖。
10. 修复发布前对比原文件状态并再次读取归属；若发生变化则放弃修复，重新走去重/新建。替换使用支持保留旧文件直至成功的操作，失败不先删除旧入口。
11. 重新读取最终路径核对关键字段，返回成功结果；在 finally 中释放已持有的互斥量、关闭 COM/进程资源、清理本次临时文件。

命名互斥量仅协调本程序在当前会话的实例，不应宣称它能阻止用户或其他软件同时编辑文件。最终复查和不覆盖的新建操作仍然必要；跨会话并发作为额外边界记录，不保证绝对无重复。

锁等待建议上限 1 秒，超时返回 `skipped/lock_busy`；另一个实例仍负责当前尝试。命名互斥量被遗弃时，取得所有权后重新完整扫描，不依赖上次执行进度。参考 [Microsoft Mutex 文档](https://learn.microsoft.com/en-us/dotnet/standard/threading/mutexes)。

### 4.5 取消、超时与残留文件

- 生命周期：`idle → running → finished`，或 `running → cancelling → finished`；终态不可再次启动。
- 任务对象在 app 生命周期内保持强引用。`QTimer.singleShot(0, task.start_once)` 只投递轻量启动动作。
- 连接 `app.aboutToQuit` 到取消入口；取消入口不能调用无上限 `join()` 或 `communicate()`。
- 用锁保护 Popen 引用与取消标志。若取消先于进程创建，不能再启动；若进程刚创建就发生取消，必须在注册时发现标志并结束它。
- 常规子进程执行预算默认 5 秒，超时后 kill 并回收；所有循环检查剩余预算。此预算不虚假承诺能中断任意正在阻塞的操作系统调用。
- 退出时 GUI 侧最多等待建议 500 毫秒，回收操作由后台继续完成；后台不持有 Qt 窗口对象。使用 daemon 线程避免异常系统调用让应用无限不退出。
- 子进程不再派生其他维护进程。强制结束后由 Python 清理已知 `temporary_link_path`；清理失败只记录 WARNING，不递归清理桌面。
- 不在启动时按通配符清除旧临时文件；崩溃导致的遗留应按请求记录识别，不能误删并发任务的文件。
- 任务被取消时若最终链接已完整发布，保留该有效入口；不为了回滚日志状态而删除成功产物。

## 6. 临时验证如何执行

### 6.1 固定验证工作区

在项目忽略目录 `test_images/shortcut_validation/<run-id>/` 中建立 `user_desktop/`、`public_desktop/`、`app_a/`、`app_b/` 和 `evidence/`。逻辑验证可用占位 EXE 文件作为链接目标；这只能证明链接属性，不能替代真实 EXE 启动验证。

创建验证夹具时至少准备：正常当前入口、重命名入口、CLI 参数入口、其他程序同名入口、受管失效入口、非受管失效入口、损坏链接、同名目录，以及仍有效的旧版本入口。

每轮记录目录清单与原文件哈希，调用内部维护接口后比对。真实桌面检查只在便携包阶段执行，不能把生产桌面路径写死在临时验证脚本里。

### 6.2 必须增加的故障注入

| 注入点 | 注入方式 | 预期断言 |
| --- | --- | --- |
| 进程协议 | 假运行器返回非 JSON、错误 ID、未知状态、非零退出码 | failed；无未捕获异常进入 GUI |
| 进程超时 | 临时固定脚本等待超过缩短后的超时 | 进程被回收；已知临时链接清除 |
| 取消竞态 | 分别在启动前、Popen 注册时、临时保存后取消 | 不产生失控子进程；最终链接不存在或完整有效 |
| 发布前变化 | 在最后复查前修改修复对象 | 不覆盖变化后的用户文件 |
| 同名新建竞争 | 发布前由另一实例占用目标名 | 复查后复用或选择新名称，不覆盖 |
| 互斥量遗弃 | 第一维护进程持锁后退出 | 下一实例能恢复，重新扫描后决策 |
| 公共桌面不可读 | 注入路径访问失败 | 明确记录扫描不完整；用户桌面可用时继续，不声称完整去重 |

### 6.3 命令与构建要求

所有命令先执行 `.\venv\Scripts\activate`。完成代码后按实际改动清单执行，例如：

```powershell
.\venv\Scripts\activate
python -m py_compile D:\Coding\MiLecFrame\src\utils\desktop_shortcut.py D:\Coding\MiLecFrame\src\gui_pyside\app.py
```

这是后续实施命令，当前新增模块尚不存在，不应在文档任务中执行。若修改更多 Python 文件，必须全部加入语法检查。

项目没有现成测试框架，用带断言的临时验证脚本实际调用模块；不要运行 pytest 或假定存在的测试套件。手工检查桌面和截图只能补充，不能替代链接属性读回。

`build_release.py` 当前没有自定义输出目录参数。先阅读其清理及 seed 数据行为，使用隔离源码副本/构建目录或按实际 PyInstaller 参数制定开发验证包命令；不能杜撰 `--output-dir`，也不能直接清理用户已有 dist。公开发行仍走项目 release 流程。
