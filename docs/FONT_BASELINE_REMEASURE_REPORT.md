## 1. 结论摘要

用户反馈"中英混排时文字明显向上偏移，体感不止 7px"。**体感描述成立，但需拆成两项性质不同的差异**（54px / `center` / `AaBbCc永和九年`，相对纯西文）：

| 项 | 量 | 性质 | 修复后 |
|---|---:|---|---|
| 西文段基线跳动 | −7px | **算法缺陷**（根因见分析报告第 5.2 节） | **归零** |
| 中文字形固有高度差 | −5px | 字体设计（现象一，用户已确认不修） | 保留 |
| 二者叠加 = 整行墨迹顶变化 | −12px | 用户实际看到的视觉变化 | 降到 −5px |

原诊断的 7px **精确量化了可修复的基线位移**；12px 是另一个口径（整行墨迹顶部），其中包含本需求下保留的字形高度差，不能用它推翻 7px 或将它全部作为补偿距离。墨迹顶部和像素加权重心有助于解释“整行看起来移动更多”的反馈，但没有感知实验能把它们直接等同于人眼感受。

本复测相对原诊断的**实际增量**是三件事：①补充整行墨迹盒和加权重心指标；②扩展真实渲染尺寸矩阵并补小字号取整样本；③提供红青差分可视化。**不改变原诊断的根因判断。**

## 3. 位移的分解与量化

### 3.1 同字号下三种口径，含义不同（关键）

54px / `center` / `AaBbCc永和九年` 相对纯西文 `AaBbCc`：

| 指标 | 位移 | 可否通过"钉死西文基线"归零 |
|---|---:|---|
| 西文段基线 | −7px | ✅ 归零（根因） |
| 西文段字形位置 | −7px | ✅ 归零 |
| 整行墨迹盒顶 | −12px | ❌ 只能降到 −5px |
| 视觉重心 Y | −8.8px | ❌ 只能降到 −1.8px |
| 墨迹中心 | −8.0px | ❌ 只能降到 −1.0px |

**分解验证**（`remeasure_verify_claims.json` → `claim_A_baseline_restore`）：
将两种字体放到同一基线后的字形范围计算得到以下残余位移。复核脚本把 `latin_glyph_shift = 0` 作为几何前提直接写入结果，并未据此执行实际像素差分；需要像素级验收时应使用独立 mask 对照：

| 字号 | 残余墨迹顶 | 残余墨迹底 | 残余墨迹中心 |
|---:|---:|---:|---:|
| 54px | −5px | +3px | −1.0px |
| 81px | −9px | +5px | −2.0px |
| 108px | −13px | +7px | −3.0px |

残余量就是中文字形相对基线的原生高度差（`永和九年` 底部下探约 0.07em、顶部更高等），**属现象一，用户已确认不修**。因此：

> −12px = −7px（可修复的基线跳动）+ −5px（不可修复的内容差异）。
> 不能用 −12px 推翻 −7px，也不能把 −12px 当作需要补偿的距离——补偿它就会再次破坏要保留的西文位置。

### 3.2 位移随字号放大（源图像素坐标）

`center` / `AaBbCc永和九年` 相对纯西文：

| 原图尺寸 | 字号 | 基线位移 | 墨迹盒顶 | 重心 Y | 占字号(基线) |
|---|---:|---:|---:|---:|---:|
| 2400×1600 | 43px | −5 | −9 | −6.5 | −11.6% |
| **3000×2000** | **54px** | **−7** | **−12** | **−8.8** | **−13.0%** |
| 4000×3000 | 81px | −10 | −19 | −12.8 | −12.3% |
| 6000×4000 | 108px | −14 | −27 | −17.7 | −13.0% |
| 2000×3000（竖图） | 54px | −7 | −12 | −8.8 | −13.0% |

规律：所测字号范围内，源图绝对位移大致随字号增大；度量、栅格化和 `//2` 取整会带来离散波动，不能视为严格正比。`min(w,h)` 决定字号，故本例横竖图**在纯文字渲染层面**取得相同位移；完整样式的方向适配另论，本复测未覆盖。

**以上均为源图像素坐标**。GUI 缩放预览或导出缩放后的屏幕位移 = 源图位移 × 缩放比，需另行换算。

**小字号取整波动**（`claim_C_small_sizes`，center 基线位移）：该脚本按实际字体度量和当前居中公式计算，基线结果又经真实 TextRenderer 渲染交叉核对。脚本中的 `ink_top_shift` 字段只表示**同基线时的字形残差**，不是当前渲染的整体顶部位移；详见[分析报告第 10.2 节](FONT_BASELINE_DIAGNOSIS.md)。

| min(w,h) | 字号 | H_L / H_M | 基线位移 | 占字号 |
|---:|---:|---|---:|---:|
| 200～450 | 12px | 15 / 18 | −2 | **16.7%** |
| 500 | 13px | 17 / 20 | −2 | 15.4% |
| 600 | 16px | 20 / 24 | −2 | 12.5% |
| 740 | 19px | 24 / 29 | −2 | 10.5% |
| 750 | 20px | 25 / 30 | −3 | 15.0% |
| 1000 | 27px | 33 / 40 | −4 | 14.8% |

小字号相对偏移更大（12px 时 16.7%）且因 `//2` 取整呈**非单调**波动，与原诊断 §5.8 一致。

### 3.3 横向位移：现象存在，但归因需更正

初稿把 `Hello世界`（108px 重心 X **+17.3px**）与 `世界Hello`（**−2.5px**）的差异归因于"bbox 当 advance"。**该归因不成立**（`claim_B_advance_vs_bbox`，108px）：

| 文本 | bbox 宽和 | advance 和 | 差 |
|---|---:|---:|---:|
| `Hello` | 280 | 280 | 0 |
| `世界` | 216 | 216 | 0 |
| `Hello世界` / `世界Hello` | 496 | 496 | 0 |
| `摄影Photo 2024永和九年` | 1289 | 1289 | 0 |
| `j` | 32 | 31 | **+1** |
| `j永` / `永j` | 140 | 139 | **+1** |

在本表的 Medium 样本中，含 `j` 的条目出现两种宽度不等。对 `Hello世界` / `世界Hello` 改用 advance 重建，**位置不变**——两者重心差异来自**内容顺序本身**（不同字形分布），加上比较基准统一用 `AaBbCc` 混入了内容差异。

干净对照（同一内容 `j永和九年`，仅推进算法不同，`claim_B_clean_contrast`）：

| 推进方式 | 段原点 x | 注册宽 |
|---|---|---:|
| 当前（bbox 宽） | [80, 96] | 232 |
| 对照（advance） | [80, 95] | 231 |
| 差 | [0, **+1**] | +1 |

**结论**：`bbox 当 advance` 是真实缺陷；本表的 Medium `j` 样本差 **1px**，不能推广为所有字体或字形的上限。例如 Gotham-MediumItalic 100px 的 `j` 可差 18px。`Hello世界` 等样本的重心大幅变化不能归因于此，初稿的横向归因**予以撤回**。量化推进误差应固定内容和字体，仅改变推进算法。

## 4. 新复测方案

原诊断已有多字号字体度量和墨迹范围；本复测进一步增加实际渲染尺寸矩阵与加权重心。所用脚本为 `remeasure_visual_shift.py`、`remeasure_visualize.py` 和 `remeasure_verify_claims.py`：

### 4.1 指标族（区分"可修复"与"内容固有"）

| 指标 | 定义 | 性质 |
|---|---|---|
| `baseline_shift` | 西文段基线位移 | **可修复根因**，验收归零 |
| `ink_top_shift` | 整行墨迹盒顶位移 | 诊断量（含内容差异） |
| `ink_bottom_shift` | 整行墨迹盒底位移 | 诊断量（现象一） |
| `ink_center_shift` | 墨迹盒中心位移 | 诊断量 |
| `gravity_shift_y/x` | 像素加权重心位移 | 诊断量 |
| `*_shift_ratio` | 位移 / 字号 | 归一化，跨字号可比 |

墨迹一律用**栅格化 mask 非零像素盒**测量（不用 `font.getbbox()`，后者是字形设计边界）。

### 4.2 样本矩阵

| 维度 | 取值 | 目的 |
|---|---|---|
| 原图尺寸 | 2400×1600 / 3000×2000 / 4000×3000 / 6000×4000 / 2000×3000 | 字号 43～108px + 竖图 |
| 文本 | 纯西文 / 1:1 混排 / 纯中文 / 中文在后 / 中文在前 / 长混排含数空 | ref_font 切换与横向推进 |
| 对齐 | top-center / center / bottom-center | 三种 alignment_offset |
| 复核样本 | `j` / `j永` / `永j` / 小字号 min=200～1000 | bbox vs advance、取整波动 |

主矩阵有 90 个 `TextRenderer.render()` 文本渲染 case 与 75 条位移对照；另 3 项主张复核主要使用字体度量、公式或独立绘制，其中并非每项都调用生产 TextRenderer。这里的真实渲染范围是文字模块，不等于完整 GUI/CLI/FrameRenderer 流程。

### 4.3 可重复性锚点

以 (3000,2000) / 54px / `center` / `AaBbCc永和九年` 为回归锚点，要求 `baseline_shift == -7` 与原诊断一致。本次实测通过。

### 4.4 差分可视化

红青差分图：**深灰 = 两组重叠墨迹**、**红 = 纯西文独有**、**青 = 混排独有**。它展示整行墨迹变化；重叠区域未必对应相同字形，红青边缘也不能直接当成某个字形的位移。每行右上角标注 `墨迹盒顶 / 重心 / 基线` 三个数值。

### 4.5 已修正的测量缺陷

初稿 `compose_line_ink` 还原坐标时误加 `pad`（应减），导致绝对坐标多算 `2×pad = 4px`。已修正并逐值验证：纯西文 `AaBbCc` 墨迹框现为 `(1531,246,1749,288)`，与独立手算一致。**相对位移不受影响**（误差在差值中抵消），故本文所有位移数值仍可复现。

## 5. 验收标准（取代初稿 §5）

> 初稿要求"修复后基线、墨迹顶、重心全部归零"——**这是错的**。加入中文后字形高度与墨迹分布本来就会变，维持西文基线并不能、也不应该强制视觉边界归零；强行归零会再次破坏要保留的西文位置。

符合需求的验收标准应为：

1. **保留现有纯西文最终基线的位置**——不能只让修复后的纯西文与混排彼此一致，必须与修复前的纯西文逐像素相同。
2. **加入或移除中文后，同一西文段的基线及字形纵向位置保持不变**（`baseline_shift == 0`，`latin_glyph_shift == 0`）。
3. **纯中文也采用样式指定西文字体的基线定位规则**。
4. **整段文字的墨迹边界和重心允许随内容变化，仅作诊断数据，不作归零目标**。其中：
   - `ink_top_shift` 修复后应降到"中文字形固有差异"水平（54px 约 −5px），**允许非零**；
   - `ink_bottom_shift` 同理（现象一，54px 约 +3px），**允许非零**。
5. **样本覆盖** 12/27/54/81/108px 五档字号（或等价原图尺寸），验证上述 1～3 在各档均成立（位移归零与字号无关，但取整路径不同需覆盖）。
6. **横向单列**：`bbox 当 advance` 的误差按[分析报告第 6.5 节](FONT_BASELINE_DIAGNOSIS.md)独立评审；本表 Medium `j` 样本约差 1px，其他字形或字重可能更大。用 `j永` 类内容一致对照量化，**不得用不同顺序文本的重心差作为证据**。

**当前算法仍不符合要求 1～3**（这是 FONT_BASELINE_DIAGNOSIS §5.2 的既有结论）；本复测进一步证实基线确实移动，**未改变根因判断**。
